# Aeri UI Governance

## Canonical repository

The canonical repository is `github.com/arjayby/aeri-ui` under the maintainer's personal GitHub account. A dedicated GitHub organization is not planned.

## Registry stewardship

Aeri UI is a Curated Registry. External contributions are welcome through pull requests, but publication remains a maintainer-owned editorial decision governed by the project's quality contracts.

## Contribution license

Contributions are accepted under the repository's MIT License.

## New Registry Items

External contributors must receive approval on a short GitHub proposal before implementing a new Component or Block. The proposal covers the Builder problem, interaction scenarios, relationship to existing shadcn items, API sketch, dependencies, accessibility risks, and expected motion and performance cost.

The maintainer may add Registry Items without opening a GitHub proposal. Maintainer-authored items still capture the same rationale in their colocated item record and must pass every publication contract.

Bug fixes, documentation improvements, and tests do not require a prior proposal.

## Security

Aeri UI will publish a `SECURITY.md` and use GitHub private vulnerability reporting and Security Advisories for coordinated disclosure. Fixes, advisories, migration guidance when needed, and tagged releases are published together. Sensitive vulnerability details must not be submitted through public Catalog forms, analytics, or public issues.
