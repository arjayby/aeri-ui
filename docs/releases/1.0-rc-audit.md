## Installation contract

Before directory acceptance, Builders must either configure:

```json
{
  "registries": {
    "@aeri-ui": "https://aeriui.dev/r/{name}.json"
  }
}
```

or install a public payload directly:

```bash
npx shadcn@latest add https://aeriui.dev/r/button.json
```

After namespace configuration, the package manager forms are:

```bash
npx shadcn@latest add @aeri-ui/button
pnpm dlx shadcn@latest add @aeri-ui/button
yarn dlx shadcn@latest add @aeri-ui/button
bunx --bun shadcn@latest add @aeri-ui/button
```

Zero configuration namespace resolution is a stable 1.0 contract only after the shadcn Registry Directory accepts `@aeri-ui`.

## Validation evidence

The release checks are:

```bash
pnpm run check
pnpm run registry:verify
pnpm run test:catalog
pnpm run test:consumer
```

Local candidate validation on 2026-07-30 passed `pnpm run check`, `pnpm run registry:verify`, and the full `pnpm run test` command. The run completed 95 Catalog tests across Chromium, Firefox, and WebKit at desktop and narrow viewports. Lighthouse reported performance `1` and accessibility `1`. The disposable Consumer Project passed with pnpm and Chromium.

The Catalog suite covers Chromium, Firefox, and WebKit at desktop and narrow viewports. CI expands the Consumer Project seam across npm, pnpm, Yarn, Bun, Chromium, Firefox, and WebKit. The Consumer Project test installs every Registry Item independently and then installs the full Launch Set together, type checks, builds, exercises accessibility and interaction, checks Consumer Theme and RTL layout, and rejects remote calls.
