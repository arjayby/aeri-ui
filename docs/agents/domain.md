# Domain docs

Aeri UI uses a single-context domain-document layout.

## Before exploring

- Read the root `CONTEXT.md`.
- Read relevant decisions under `docs/adr/`.
- If either is absent, proceed without requiring it to be created.

## Vocabulary

Use the canonical terms defined in `CONTEXT.md` in issues, specifications, tests, and implementation discussion. Avoid synonyms that the glossary explicitly rejects.

If a required concept is absent, reconsider whether new terminology is necessary or record the gap for domain modeling.

## Architectural decisions

Surface conflicts with existing ADRs explicitly. Do not silently override an accepted decision.
